# wuwa-calc-data

Character/weapon/echo mechanics and image assets for [wuwa-calc-site](https://github.com/jjc-astra/wuwa-calc-site)
(the site repo). Kept separate so publishing new data doesn't require rebuilding or redeploying
the site.

The deployed site fetches straight from this repo's raw content
(`raw.githubusercontent.com/<owner>/wuwa-calc-data/main/...`), so this repo needs to stay
**public** and needs no build step of its own.

`data/manifest.json` is a relPath -> content-hash map the site uses to detect when cached data is
stale. The pre-commit hook in `.githooks/` regenerates it and the rankings index into every commit
that touches `data/` or `images/` (enable once per clone: `git config core.hooksPath .githooks`).
`.github/workflows/manifest.yml` regenerates both again on push, as a fallback for commits made
without the hook (e.g. on GitHub); then it commits, and you need to pull.

## Rotation Rankings (`data/character_results/`)

A submission is one file: the site's Export Rotation dialog downloads `rotations/<name>.json`, the
rotation, the roster and target (`enemy`) as submitted, and its settings, plus a short `hash` of
those. Set `rotationType` to `"linear"` or `"quickswap"` (in the dialog or by hand) to classify it.

Everything else is generated; don't edit it by hand:

- `results/Results_<name>.json` -- `Rotation_<name>.json` calculated with the unit's recommended
  substats and its weapon at R1 (everything else as submitted) on the default target: DPS +
  contribution. Generated by the site repo's `npm run recalc:results -- --repo`, which also deletes
  results files whose rotation is gone. Rerun it after data changes that affect damage.
- `index.json` -- what Rankings search, filters and sort read, built from the results by
  `scripts/generate-rankings-index.mjs` (run by the recalc, by the workflow, or `npm run gen`).

`node scripts/generate-rankings-index.mjs --check` exits 1 if the index is out of date; the site's
`npm run check:results -- --repo` does the same for the results.
